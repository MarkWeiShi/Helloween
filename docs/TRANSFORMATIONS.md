## Runtime behavior

Both the globe character dialog and every character's invitation use `src/transformation-player.ts`. A version 1 manifest at `/art/transformations/manifest.json` maps catalog IDs to `entrance`, `loop`, `poster`, `duration`, `loopDuration`, and `revealAt`. Optional alpha WebM URLs are publication artifacts; this runtime uses MP4 with WebGL chromakey and a Canvas 2D chromakey fallback when the browser cannot create a WebGL context. The fallback composites at 360 × 640 while preserving the same video, audio, crop and lifecycle behavior. Same-origin hashed URLs are supported. The introduction runs to its actual media end, then hands off to a second video element containing the separately generated action loop with native infinite looping. Both sources preload alongside the intro; the canvas retains the intro frame until loop playback is ready. Durations are metadata, not substitute animation timers.

The globe character view starts playback on opening and provides a replay control after the introduction. The existing microphone gate remains. On an unmeasured first transformation, the reveal cue starts a three-second local pitch/volume measurement. Only numeric scores are stored in this browser; reopening does not repeat an existing score measurement. Closing, changing character, hiding the tab or leaving the page cancels capture. Closing is always available; media/microphone load waits are bounded. Background playback pauses and requires explicit replay.

The invitation acceptance button opens the same immersive character view as a globe click, using the invited character ID. Both contexts play with sound enabled at 0.65 volume and share the local first-measurement behavior. Acceptance does not upload a recording. The separate invitation recording helper can upload only when explicitly wired to its recording action; it is not invoked by this acceptance path. Pausing for a hidden tab displays a replay instruction.

Missing metadata/media or failure of both available rendering paths leaves a poster (or the original portrait if no manifest entry exists) and an explicit retry. Failed manifest fetches and missing entries are re-fetched on retry. No static zoom is passed off as transformation video. An audio playback rejection also remains retryable. WebGL resources, animation frames and video sources are released on close. HTTP tests may inject a separate `staticRoot` so concurrent production builds cannot delete an in-progress audit snapshot; the default remains `dist/`.

`server/index.mjs` serves MP4/WebM with correct MIME, byte range seeking and HEAD; the manifest revalidates. Run `npm test` and `npm run build`. Unit tests exercise both renderers, source transition, infinite loop, reveal-once cue, persistence isolation, missing-entry retry and lifecycle cleanup using browser doubles. HTTP tests exercise actual server range responses and isolated static roots. Browser evidence is separate from these unit tests and remains scoped to the browser and assets recorded in the audit.
